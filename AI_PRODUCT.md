# AI Coach — продуктовая спецификация

**Статус:** проектное предложение; AI Coach в текущем приложении не реализован.

## Назначение и цели

AI Coach — русскоязычный аналитик тренировок и прогресса, использующий данные GymForTeenage только для ответа на относящиеся к ним вопросы. Он доступен через карточку на главной и блок AI Insights в статистике; оба сценария используют единый сетевой и контекстный слой.

Цели: давать конкретные выводы, объяснять основания, бережно относиться к данным и не вмешиваться в пользовательскую запись тренировок. AI работает только на чтение. Он не назначает медицинское лечение и не подменяет тренера или врача.

## Сценарии и приёмка

| Возможность | Сценарий и ожидаемый результат / критерий приёмки |
|---|---|
| Карточка главной | Пользователь нажимает компактную violet-карточку под шапкой и попадает в новый чат. Не появляется пятая вкладка или плавающая кнопка. |
| Настройки AI | Пользователь включает AI, вводит ключ, сохраняет, проверяет подключение, заменяет или удаляет ключ. Секрет после сохранения маскирован; состояние и ошибки ясны. Без ключа функция объясняет, как настроить подключение. |
| Первое использование | При первом запросе с персональным контекстом приложение объясняет, что выбранные категории отправляются Google Gemini, перечисляет возможные категории и просит явное согласие. Без согласия персональные данные не отправляются. Согласие само по себе не включает AI, если AI выключен. Для общего теоретического вопроса без данных приложения персональное согласие не требуется. |
| Insights | В статистике доступен обзор последних семи локальных календарных дней. До трёх последних завершённых тренировок за 30 дней допустимы только как сравнительный контекст и не входят в недельный итог. «Подробнее» открывает новую сессию чата с текущей сводкой как стартовым контекстом. |
| Нет данных | При отсутствии подходящих тренировок или измерений Insights сообщает об этом без выдуманных значений. |
| Чат об упражнении | На вопрос о жиме передаются только совпавшая история упражнения, даты, подходы, вес, повторы и статус; ответ указывает период и фактические основания. Неоднозначность названий требует уточнения. |
| Чат о воде/измерении | Передаются только соответствующие записи и запрошенный период. Остальные категории не включаются. |
| Теоретический вопрос | На общий вопрос без связи с личными данными контекст приложения не отправляется. |
| Follow-up | После вопроса о жиме реплика «а почему так?» использует активную область жима. Явная смена темы строит новую область; неопределённость не приводит к передаче всей базы. |
| Ошибка или offline | Предыдущий Insights остаётся доступен с отметкой устаревания; пользователь видит понятную ошибку и ручной повтор. Повтор ограничен, интерфейс не зависает. |
| Закрытие чата | Закрытие удаляет сообщения и activeContextScope из памяти сессии; следующий чат начинается пустым. |

## Insights и актуальность

Сводка строится по завершённым тренировкам за последние семь локальных календарных дней. Сравнительные примеры — не более трёх последних завершённых тренировок в пределах 30 дней. Старые записи не попадают в недельный итог. Кэш пересматривается после любого изменения входных данных, способного повлиять на сводку: завершения, изменения или удаления тренировок, импорта другого backup, изменений релевантных измерений и наступления новой локальной календарной даты. Не запускать генерацию при изменениях каждого подхода, обычном повторном открытии статистики или запуске приложения. При offline сохранить признак необходимости обновления; при ошибке не терять последний результат.

Состояния UI: AI отключён, нет ключа, ожидание подключения, загрузка, актуальная и устаревшая сводка, ошибка и ручный повтор. Пересчёт может выполняться при следующем открытии статистики или подходящей возможности приложения, но не создаёт фоновых бесконечных запросов.

## Приватность, безопасность и возрастная аудитория

Передаваемые сведения ограничиваются темой запроса: конкретная история упражнения, записи воды, релевантные измерения либо агрегаты недельной статистики. Не отправляются API-ключ, локальные UUID, настройки, каталог целиком, несвязанные метрики и полная база. Общий теоретический запрос не содержит данных приложения. Google Search Grounding выключен.

При первом использовании персонального контекста пользователь отдельно подтверждает передачу выбранных данных Google Gemini. До подтверждения сетевой запрос с пользовательскими данными запрещён; отмена/отказ оставляет чат доступным для вопросов без личных данных. Согласие не меняет переключатель AI. Точный текст должен объяснять категории и цель передачи. Не обещать, что Google гарантированно не хранит или не использует данные: до выпуска проверить актуальные официальные условия Gemini API и отразить подтверждённые условия в UI.

Ключ хранится в iOS Keychain (`Security.framework`), вне UserDefaults и JSON backup. HTTP передаёт его заголовком `x-goog-api-key`; ключ не логируется. Прямой ключ в IPA можно извлечь: Keychain защищает локальное хранение, но не даёт серверной изоляции секрета. Для приложения одного человека это осознанный компромисс без собственного backend.

Поскольку приложение ориентировано на подростка, ответы должны быть уважительными, без стыда, давления, экстремальных диет, опасных нагрузок и неподтверждённых медицинских утверждений. При боли, травме, болезни, нарушениях питания или вопросах лечения AI рекомендует обратиться к родителю/опекуну и квалифицированному медицинскому специалисту; срочная опасность требует немедленной помощи взрослого/экстренных служб. Не выводить возраст и личность из тренировочных данных. Не выдавать общие рекомендации за индивидуальное медицинское назначение.

## Хранение и ошибки

| Данные | Срок и место |
|---|---|
| API-ключ | Keychain; удаляется по действию пользователя |
| Сообщения и activeContextScope | Только оперативная память открытой сессии; удаление при закрытии |
| Последний Insights | Отдельный версионированный локальный кэш, не часть backup |
| Тренировки и прочие пользовательские данные | Существующее хранилище Store |
| JSON backup | Существующая версия и схема; ключ, сообщения и AI-кэш исключены |

Понятно различать отсутствие сети, неверный ключ, запрет/регион, ограничения квоты, HTTP 5xx, таймаут, отмену, пустой/невалидный ответ и чрезмерный контекст. HTTP 403 не считать автоматически ошибкой ключа. Учитывать `Retry-After`, применять ограниченный exponential backoff, не дублировать одновременные запросы. При закрытии чата отменять запрос; отмена не показывается как ошибка.
